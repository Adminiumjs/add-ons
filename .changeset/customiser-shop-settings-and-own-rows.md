Customiser: the set-up page has **Shop settings**, where the shop keeps its one-colour line (where light becomes dark when a shopper makes their logo one colour), a new page's bleed and safe line, the thinnest line and the sharpness a picture needs; Adminium's own add-on settings screen draws only settings a manifest declares, and the Customiser keeps its own in a table. The settings are one row for the whole install, covering every shop app on it, and the dialog says so; an app's role may now change them (`appGrants`), every one but the unit sizes are shown in, which nothing reads yet. The README's grants keep each app's roles to the app's own rows by its `app` column: a shop's owner sees, changes and removes only its own app's set-up and makes rows only for it, reads and fills the starter fonts but never removes one, and no app's role makes a font a starter or takes one out of the set (`starter` is no longer an app's to change). The proof-maker's grants read the settings, so its proof uses the shop's own line, and read only the app's own customers' designs, versions and files: on an install running Maker Shop and Print Shop, neither app's staff read the other's customers' words or logos. "New base" offers only the shop apps the reader's role works for, so an app's owner is never offered the other's.
